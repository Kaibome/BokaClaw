# Dashboard internationalization (EN / ZH)

The dashboard ships two locales, English (`en`) and Simplified Chinese (`zh`). URLs do not change; the selected locale is stored in a cookie and resolved on the server so SSR and the client agree on the first paint.

## Files

| Path | Purpose |
|------|---------|
| `dashboard/src/i18n/config.ts` | `Locale`, supported locales, cookie name, `Accept-Language` negotiation, `<html lang>`/`Intl` mappings |
| `dashboard/src/i18n/messages/en.ts` | English dictionary (source of truth); exports `MessageKey` and `Messages` |
| `dashboard/src/i18n/messages/zh.ts` | Chinese dictionary, typed as `Messages` so missing/extra keys fail `tsc` |
| `dashboard/src/i18n/translate.ts` | Lookup, `{placeholder}` interpolation, `Intl.PluralRules` plural selection |
| `dashboard/src/i18n/provider.tsx` | `I18nProvider` + `useI18n()` |
| `dashboard/src/i18n/format.ts` | date-fns/`Intl` helpers (dates, relative time, numbers, compact numbers) |
| `dashboard/src/i18n/server.ts` | `resolveLocale()` (cookie → `Accept-Language`) and `getServerMessage()` for metadata |
| `dashboard/src/components/i18n/language-switcher.tsx` | Top-bar dropdown and Settings inline variants |

## Locale resolution and persistence

1. On the server, `resolveLocale()` reads the `bokaclaw_locale` cookie. If absent, it negotiates the first supported language from `Accept-Language` (`zh*` → `zh`, `en*` → `en`, otherwise English).
2. Each root layout (`(root)`, `(auth)`, `setup`) passes the resolved locale into `I18nProvider` and sets `<html lang>`.
3. Switching language updates the React context, writes the cookie (`path=/`, one year, `SameSite=Lax`), updates `document.documentElement.lang` and `document.title`, and refreshes the UI immediately.
4. A reload or hard navigation re-reads the cookie. Language preference is not sensitive and is intentionally readable by JavaScript; auth tokens are not involved.

Because the root layouts read cookies and headers, these routes are dynamically rendered rather than statically prerendered. This is expected for the self-hosted, auth-gated dashboard.

## Using translations

```tsx
"use client";

import { useI18n } from "@/i18n/provider";

const { t, formatNumber, formatDate, formatRelativeTime } = useI18n();
t("settings.title");
t("memories.range", { start: 1, end: 20, total: 42 });
```

```tsx
// Server component, e.g. generateMetadata
import { getServerMessage, resolveLocale } from "@/i18n/server";

const locale = await resolveLocale();
const title = getServerMessage(locale, "meta.dashboard.title");
```

`t` has a stable identity across renders, so it is safe to use inside `useCallback` / `useEffect` without causing re-subscriptions. Hooks that surface localized error strings (`use-api-query`, `use-agent-chat`) keep the text in refs so a language switch does not refetch data.

### Adding a string

1. Add the key to `src/i18n/messages/en.ts`.
2. Add the same key to `src/i18n/messages/zh.ts`. `tsc` fails if either file is out of sync.
3. Replace the literal with `t("namespace.key")`. Use `{name}` placeholders for values and `key.one` / `key.other` for plurals:

```ts
"memories.count.one": "{count} memory",
"memories.count.other": "{count} memories",
```

### What stays untranslated

Brand names, model names, tool names, API paths, HTTP methods, URLs, code samples, run IDs, and backend-supplied error `detail` text. Only local fallbacks and user-readable enum labels are translated.

## Dates and numbers

Use the helpers from `useI18n()` instead of `date-fns` or `toLocaleString()` directly:

- `formatDate(value)` → `PP` (e.g. `Nov 7, 2026` / `2026年11月7日`)
- `formatDateTime(value)` → `PPpp`
- `formatRelativeTime(value)` → localized "3 minutes ago" / "3 分钟前"
- `formatNumber(value)` and `formatCompactNumber(value)` → localized digits/grouping

Token abbreviations from `formatTokens` (`k`, `M`) and `ms` are intentionally left as-is.

## Adding a locale

1. Add the locale to `LOCALES` in `config.ts` and extend `HTML_LANG`, `INTL_LOCALE`, `LOCALE_LABELS`.
2. Add `messages/<locale>.ts` typed as `Messages`.
3. Register it in `messages/index.ts`.
4. Add a date-fns locale mapping in `format.ts`.

## Verification

```bash
cd dashboard
pnpm typecheck
pnpm lint
pnpm build
```

Manual checks: clear the cookie and send `Accept-Language: zh-CN` (Chinese first paint) and `en-US` (English); switch in the top bar and Settings; reload to confirm persistence; check `<html lang>`, metadata titles, dates, relative times, toasts, dialogs, aria-labels, collapsed nav tooltips, and the Agent chat error/empty states.
