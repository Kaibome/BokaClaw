The one-time migration reads the legacy `postgres.memories` table and `/app/history/history.db`.
It never modifies or drops the old data.

```bash
# Preview
python scripts/migrate_mem0_to_workspace_memory.py --dry-run

# Write Markdown files, index rows, and audit rows
python scripts/migrate_mem0_to_workspace_memory.py --verify

# Map a legacy non-UUID scope explicitly
python scripts/migrate_mem0_to_workspace_memory.py \
  --user-map pankaibo=<user-uuid>
```

## What it does

1. Reads `id` and `payload` from the legacy `memories` table.
2. Maps `user_id`: UUID scopes pass through; with exactly one dashboard account, non-UUID scopes map
   to that account (logged); otherwise pass `--user-map`.
3. Writes research conclusions to `memory/<date>.md` under `Research`; everything else to
   `MEMORY.md`.
4. Preserves `created_at`, `updated_at`, `question_key`, and `sources`; research entries get an
   expiry from `AGENT_RESEARCH_MEMORY_TTL_DAYS`.
5. Copies SQLite history rows into `memory_history`.
6. Backs up the source rows and `history.db` under `.backup/<timestamp>/`.

The migration is idempotent: a row whose id already exists is skipped. The old tables remain
available until you remove them after the retention window.
