# Hermes ReAct 循环异常处理机制

> 范围：`agent/conversation_loop.py` 的主循环及其 `agent/turn_*.py` 阶段模块、API 错误分类与恢复、响应校验、工具执行、落库与收尾。
>
> 目标：说明一次 ReAct 回合（模型推理 → 工具调用 → 观察 → 再推理）中，异常在每一层如何被拦截、恢复或终结。
>
> 相关：[`exception-handling.md`](exception-handling.md)（BokaClaw）、[`exception-handling-claw-code.md`](exception-handling-claw-code.md)（claw-code）、[`exception-handling-comparison.md`](exception-handling-comparison.md)（三者对比）

## 设计原则

1. **异常不逃逸**：任何一层的异常都会被转成结构化结果（错误响应、tool 结果、失败回合），不会直接抛给调用方。
2. **恢复有界**：一次性修复标志、重试次数、压缩尝试次数、恢复阶梯轮数、外层错误上限共同保证不会无限循环。
3. **缓存安全**：恢复要么重建请求，要么只改消息尾部；压缩是唯一允许改写历史的操作。
4. **可解释**：每次终止都带 `turn_exit_reason`、`failure_reason` 和可重试性标记，供 CLI、网关、TUI/Desktop 渲染成用户能理解的下一步。

## 一、请求准备层

在真正发出模型请求之前：

| 机制 | 行为 |
|---|---|
| 上下文预检压缩 | 压缩超时：退款本次 API 调用并直接结束回合，不发送必然超限的请求 |
| 压缩锁 / 冷却 | 暂时延迟压缩，本轮继续或软延迟到下一次安全边界，不反复空转 |
| 压缩无效阻断 | 连续压缩没有明显收益时停止预检重试，避免每轮重复付费 |
| 消息修复 | 修复角色交替违规、损坏的 tool 参数、无效回放项，避免发出必然失败的请求 |
| Ollama 上下文地板 | 运行时窗口不足以承载工具调用时直接给出可读终止原因，不重试 |
| `pre_llm_call` 钩子否决 | 不产生模型调用，回合以"被拦截"结束 |

## 二、provider 调用层

### 2.1 错误分类

失败先经过统一分类，而不是看到异常就重试。分类覆盖：

- 鉴权：临时失效、永久失效
- 计费：余额/额度耗尽、免费层拒绝、用量窗口
- 限流：账户限流、上游聚合器限流、上游 WAF/CDN 封禁
- 服务端：过载（503/529）、5xx、连接/读取超时、TLS 证书失败
- 请求形状：上下文溢出、413、图片过大/损坏、模型不存在、格式错误、角色交替违规、加密回放失效、多模态工具内容不支持、推理参数被拒
- 策略：内容策略拒绝、数据策略拒绝、模型权限不足
- provider 特例：Anthropic 思考签名、长上下文分层、OAuth 1M beta、llama.cpp grammar 等
- 未知错误：按可重试处理，带退避重试

每个分类同时给出恢复提示：是否可重试、是否应压缩、是否应轮换凭证、是否应切换 fallback。

### 2.2 一次性修复链

分类之后、通用重试之前，按固定顺序尝试针对性修复。每条修复在一次 API 调用尝试内最多触发一次：

1. 免费层/欢迎层路由修复
2. 计费受限时收缩输出预算
3. 推理配置被拒时只移除不被支持的开关
4. Nous 付费权益刷新
5. Codex 过期推理回放剥离
6. 凭证池刷新与轮换
7. 图片过大时原地缩小
8. 工具消息中的图片/多模态内容降级
9. 损坏图片剥离
10. OAuth 长上下文 beta 关闭
11. provider 特有的 401 刷新
12. 格式类错误的字段剥离与重建

修复成功则直接重试；失败则进入通用重试。

### 2.3 重试与退避

- 默认重试次数：`agent.api_max_retries` = 3（含首轮外的额外尝试）。
- 退避：抖动指数退避，约 2 秒起步、60 秒封顶；provider 返回 `Retry-After` 时优先采用。
- 限流和特定 provider 过载使用自适应退避策略。
- 等待过程可被用户中断；中断会立即结束等待并返回中断结果。
- 重试消息会被缓冲，只有全部失败时才一次性展示，避免刷屏。

### 2.4 fallback 切换

按错误类型决定切换时机：

- 限流 / 计费：立即切换。
- 传输类错误：先重试一次，仍失败再切换。
- 鉴权错误：刷新凭证后仍失败才切换。
- 上游聚合器限流：凭证池无法解决，直接切换。
- 内容拒绝 / 数据策略：确定性失败，不切换（或按 provider 策略终止）。

fallback 链本身也会跳过不可用、未配置或端点不匹配的候选；切换后重建客户端、模型标识和运行时能力，并从新 provider 的上下文窗口重新预检。

### 2.5 自动恢复阶梯

重试和 fallback 都耗尽后，对**瞬时故障**（5xx、过载、超时）再尝试最多 5 个恢复周期：

- 等待约 15 / 30 / 60 / 60 / 60 秒，带抖动；provider 的 `Retry-After` 可覆盖，上限 120 秒。
- 仅当尚未向用户输出正文时生效，避免重复输出。
- 用户中断会取消等待；鉴权、格式、策略、计费类错误不进入阶梯。

### 2.6 终止

最终失败时返回结构化结果：错误文案、失败原因、是否可重试。UI 据此决定是建议重试、切换模型、压缩上下文还是修正配置。

## 三、响应校验层

模型返回了，但输出本身有问题：

### 3.1 非法 / 空响应

- 响应结构非法或为空：先重试 → 提前 fallback（空响应常与限流相关）→ 终止。
- Codex/Responses 的软失败、SSE 200 后报错、只有推理无回答：分别走续写、分类或剥离回放后重试。

### 3.2 截断（`finish_reason=length`）

- 文本截断：追加续写提示，最多 4 次；片段会被拼接。
- 工具调用参数被截断：提升输出预算后重试；无法安全解析则拒绝执行并给 partial 结果。
- 思考预算耗尽：单独处理，避免继续消耗同一预算。
- 续写达到上限：丢弃片段链，输出明确终止原因。

### 3.3 空内容 / 只有思考块

固定阶梯：

1. 流式残片恢复
2. 复用上一轮内容（仅限 housekeeping 工具场景）
3. 工具调用后的一次性提示
4. 思考完成提醒（最多 2 次）
5. 空响应重试（默认 3 次；高成本空响应会提前降到 1 次）
6. fallback provider
7. 输出 `(empty)` 哨兵并终止

### 3.4 重复退化

- 流式过程中和结束时都检测长片段重复。
- 触发后中断回合，避免把循环字节写回历史（否则下一轮会被重新诱发）。
- 对"用户明确要求重复"的输出保持保守，不会误杀。

### 3.5 其他输出异常

- 不完整 `<REASONING_SCRATCHPAD>`：重试 2 次后按 partial 保存。
- 只有推理的干净停止：在可信路由上把推理提升为最终回答，但不写进普通的 assistant 正文。
- 内容过滤导致流中止：优先切换 fallback，并回滚不完整片段。

## 四、工具执行层

| 异常 | 处理 |
|---|---|
| 未知工具名 | 返回错误结果让模型自纠；连续 3 次才终止为 partial |
| 混合批次含非法调用 | 只对非法调用返回错误，合法调用继续执行 |
| 参数 JSON 非法 | 重试 3 次后注入恢复用 tool 结果，保持角色交替合法 |
| 参数被截断 | 拒绝执行并返回 partial 结果，不猜测参数 |
| handler 抛异常 | 统一转成 tool error 结果，循环继续，模型可自行恢复 |
| 工具超时 | 并发批 / 单次调用各有截止时间；超时生成超时结果并中断工作线程，交互式工具豁免 |
| 用户中断 | 剩余工具调用跳过，每个补一条 cancelled 结果，保证 tool_call/result 配对完整 |
| 审批拒绝 / 护栏阻断 | 变成工具结果；触发硬护栏则受控中止回合并输出解释 |
| 结果过大 | 截断并溢出到文件，附读取指针，不视为错误 |
| 执行前落库失败 | 不执行工具，直接结束回合 |
| 执行后落库失败 | 不基于"只在内存里"的结果继续推理，结束回合 |

此外，工具结果中的不可信内容会被包裹标记，异常文本会被清洗，避免把错误信息变成结构性噪声或提示注入载体。

## 五、回合外层兜底

外层捕获包住整个响应处理块：

| 情况 | 处理 |
|---|---|
| 解释器正在关闭 | 立即结束，尽力保存，不重试 |
| 确定为本地后处理 bug | 不重试，直接结束，避免烧光迭代预算 |
| 其他未预期异常 | 重试，但每回合最多 8 次 |
| 接近迭代上限 | 提前收口，避免在预算边缘反复失败 |
| 未回答的 tool_call | 自动补错误结果，保证消息结构合法 |

## 六、收尾阶段

- finalizer 的每个步骤独立守护：标题生成、轨迹保存、资源清理、持久化、微压缩，一个失败不影响其他步骤。
- 已经流给用户的文本不会因后续步骤抛错而丢失。
- 持久化有去重标记和一次自愈重试；失败会记录告警并依赖后续重试。
- 异常退出原因映射为失败码与可重试性，供各端渲染。
- 若回合停在工具结果上且没有后续文本，会合成一条可见的收尾说明，避免"静默停止"。

## 七、贯穿性机制

### 7.1 压缩失败处理

- 摘要失败默认提交确定性兜底摘要（可配置为直接中止）。
- 超时/停滞按 60s → 300s → 900s 阶梯冷却。
- provider 实证的上下文溢出可绕过冷却一次。
- 连续摘要服务过载会先中止、多次后降级为兜底摘要，避免整个会话被重置。
- 每回合压缩尝试次数有上限（默认 3）。

### 7.2 跨会话熔断

- Nous 账户级限流会写入共享状态，让同一 profile 的所有会话一起退避。
- 凭证池按错误类型设置不同冷却：计费、限流、鉴权互不混淆。
- fallback 切换会尊重 provider 给出的重置时间，避免在不可用窗口内反复切换。

### 7.3 存活检测

- 回合级 liveness watchdog：默认 600 秒没有任何活动则强制中止，防止租约一直续期但回合实际卡死。
- 工具调用有独立截止时间；流式调用有进度检测。
- 网关侧有心跳与不活动超时，避免长工具导致会话被判死。

## 八、恢复上限汇总

| 机制 | 默认 / 上限 |
|---|---|
| API 重试 | 3 次 |
| 退避 | 约 2s 起步、60s 封顶，带抖动；`Retry-After` 优先 |
| 自动恢复阶梯 | 5 个周期（15/30/60/60/60 秒） |
| 外层异常 | 每回合最多 8 次 |
| 压缩尝试 | 默认 3 次 |
| 空响应重试 | 默认 3 次；高成本时降到 1 次 |
| 思考完成提醒 | 2 次 |
| 不完整 scratchpad | 2 次 |
| 文本续写 | 4 次 |
| 未知工具名 | 3 次 |
| 非法 JSON 参数 | 3 次 |
| 一次性修复标志 | 每次 API 尝试各触发一次 |
| 可退款重启 | 受重试次数约束，防止无限退款 |
| 回合存活检测 | 600 秒无活动强制中止 |
